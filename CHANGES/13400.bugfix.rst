Fixed responses and requests with multiple ``Content-Encoding`` codings (e.g. ``Content-Encoding: gzip,gzip`` from a server that compresses twice) being passed through undecoded. Up to 2 supported codings are now decoded in reverse order of application; longer chains raise :exc:`~aiohttp.http_exceptions.ContentEncodingError` instead of silently returning compressed bytes. Coding tokens are now matched case-insensitively, and repeated ``Content-Encoding`` headers are handled as one comma-separated list -- by :user:`Dreamsorcerer`.
